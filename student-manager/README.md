# REVERA Compass (데스크 공용 학생관리)

데스크 선생님들이 함께 쓰는 학생 관리 웹사이트입니다. 외부 서비스 없이 독립적으로 동작합니다.

- **서버**: Node.js (Express)
- **DB**: SQLite 파일 1개 (`data/revera.db`). 백업은 이 파일을 복사하면 됩니다.
- **로그인**: 자체 계정(이메일 + 비밀번호). 관리자가 선생님 계정을 만들어줍니다.

## 기능

| 화면 | 내용 |
|---|---|
| 대시보드 | 진행 중 학생 수, 내 담당 학생, 14일 내 지원 마감, 밀린 할 일 / 30일 내 마감 목록 / 최근 상담 / 할 일 체크리스트 |
| 학생 | 검색(이름·학교·태그·학부모), 상태·담당자 필터, 학생 등록 |
| 학생 상세 | 상담기록(작성자·수정자 표시, “다음 할 일” + 기한), 지원대학(전형·마감·진행상태·에세이 단계), 프로필 |
| 마감일정 | 전체 학생의 지원 마감을 날짜순으로 표시(D-day, 지난 미제출 건은 빨간색) |
| 선생님 관리 | (관리자) 계정 추가·비활성화·비밀번호 초기화, 관리자 지정, **DB 백업 다운로드** |

공동 사용과 보안:
- **동시 수정 방지**: 다른 선생님이 먼저 저장한 항목을 덮어쓰려고 하면 저장이 거부되고 안내가 표시됩니다.
- **변경로그**: 누가 언제 무엇을 만들고, 고치고, 지웠는지를 DB의 `log` 테이블에 기록합니다.
- 열어둔 화면은 2분마다 자동으로 새로고침됩니다.
- 학생 삭제는 관리자만 할 수 있습니다. 일반 선생님은 상태를 `종료`로 바꿔서 보관합니다.
- 비밀번호는 scrypt 해시로 저장하고, 원문은 저장하지 않습니다.
- 같은 이메일로 로그인에 5번 실패하면 15분간 잠깁니다.
- 새 계정은 첫 로그인 때 비밀번호를 바꿔야 사용할 수 있습니다.
- 선생님을 비활성화하면 그 즉시 로그아웃됩니다.

## 내 컴퓨터에서 실행해보기

[Node.js](https://nodejs.org) 20 이상(LTS 버전 권장)이 필요합니다.

```bash
cd student-manager
npm install
npm run demo                          # 샘플 데이터가 든 데모 DB 생성
DB_PATH=data/demo.db npm start        # http://localhost:3000
# 로그인: admin@demo.test / demo-pass-1
```

Windows PowerShell에서는 `$env:DB_PATH="data/demo.db"; npm start` 로 실행합니다.

## 실제 운영 시작

```bash
npm install
npm run admin -- create 원장님이메일@example.com 원장님이름 "처음비밀번호8자이상"
npm start
```
접속한 뒤 **선생님 관리 → + 선생님 추가**로 선생님 계정을 만들고, 임시 비밀번호를 각 선생님께 직접 전달합니다.

### 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 포트 |
| `DB_PATH` | `./data/revera.db` | DB 파일 위치. **클라우드에서는 반드시 영구 저장소(볼륨) 경로로 지정** |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | – | 계정이 하나도 없을 때 첫 실행에서 관리자를 자동 생성 (명령어를 쓸 수 없는 클라우드용) |
| `TRUST_PROXY` | – | `1`: HTTPS 프록시/클라우드 뒤에서 실행할 때 (접속자 IP 인식) |
| `COOKIE_SECURE` | – | `1`: 로그인 쿠키를 HTTPS에서만 전송 (HTTPS로 운영할 때 권장) |

## 어디에 띄울까 (배포 방법)

### A. 학원 PC에 설치 (내부망 전용)
- 항상 켜두는 PC 한 대에 위 “실제 운영 시작” 순서대로 설치합니다.
- 같은 와이파이/네트워크에 있는 선생님은 `http://그PC의IP:3000`으로 접속합니다. PC의 IP는 Windows에서 `ipconfig`로 확인합니다.
- 비용이 들지 않고 데이터가 학원 밖으로 나가지 않습니다.
- 대신 **학원 밖에서는 접속할 수 없습니다.** 이 PC를 인터넷에 직접 열어두는 것(포트포워딩)은 권장하지 않습니다. HTTPS가 없어서 비밀번호가 암호화되지 않은 채로 전송됩니다.
- PC가 고장나면 데이터도 잃을 수 있으니 **백업 다운로드를 정기적으로** 해두세요.

### B. 클라우드 — Railway (권장, 어디서나 접속)

> 아래 버튼 이름과 메뉴 위치는 2026년 10월 기준이며, Railway 화면이 바뀌면 다를 수 있습니다.
> 요금(공식 문서 기준): Hobby 플랜 **월 $5**이고, 그 $5가 사용량 크레딧으로 포함됩니다. 볼륨은 서비스당 기본 **5GB**입니다.
> 이 사이트 규모면 $5 안에서 해결될 것으로 예상하지만 실측한 값은 아닙니다. 첫 달에 **Usage** 화면에서 실제 사용량을 확인하세요.

1. **가입**: https://railway.com 에서 GitHub 계정으로 가입하고 **Hobby 플랜**을 결제합니다.
   무료(Free/Trial) 플랜은 볼륨이 0.5GB이고 사용량 제한이 있어서 운영용으로는 권장하지 않습니다.
2. **프로젝트 생성**: **New Project → Deploy from GitHub repo**에서 `revera-assessment` 저장소를 고릅니다.
   GitHub 권한을 묻는 창이 뜨면 이 저장소에 대한 접근을 허용합니다.
3. **서비스 설정** (생성된 서비스 클릭 → **Settings**)
   - **Source → Root Directory**: `/student-manager`
   - **Source → Branch**: 사이트 코드가 있는 브랜치를 고릅니다(main에 합친 뒤라면 `main`).
   - **Config-as-code → Railway Config File**: `/student-manager/railway.json`
     설정 파일은 Root Directory를 따라가지 않아서 전체 경로로 적어야 합니다. 이 칸을 비워둬도 Dockerfile을 자동으로 찾아 배포하고, 상태 확인(health check)만 빠집니다.
4. **볼륨 추가 (가장 중요)**: 프로젝트 화면에서 서비스를 우클릭하거나 **+ Create → Volume**을 눌러 볼륨을 만들고, 이 서비스에 연결합니다.
   - **Mount path**: `/data`
   - 이 단계를 빼먹으면 재배포할 때마다 **모든 데이터가 사라집니다.**
5. **환경변수** (서비스 → **Variables**)

   | 이름 | 값 |
   |---|---|
   | `ADMIN_EMAIL` | 원장님 이메일 |
   | `ADMIN_NAME` | 원장님 이름 |
   | `ADMIN_PASSWORD` | 처음 비밀번호(8자 이상) |
   | `TRUST_PROXY` | `1` |
   | `COOKIE_SECURE` | `1` |

   `PORT`는 Railway가 자동으로 넣어주니 직접 넣지 않습니다.
6. **주소 만들기**: **Settings → Networking → Generate Domain**을 누르면 `https://xxxx.up.railway.app` 주소가 생깁니다. 이 주소가 사이트입니다.
   학원 도메인(예: `students.revera.co.kr`)을 쓰려면 같은 화면의 **Custom Domain**에 입력하고, 안내에 나오는 DNS 레코드를 도메인 업체 설정에 추가합니다.
7. **배포 확인**: **Deployments** 탭에서 배포가 *Success*가 되면, 위 주소로 접속해 `ADMIN_EMAIL` / `ADMIN_PASSWORD`로 로그인합니다.
8. **마무리 보안 조치**
   - 로그인한 뒤 바로 **비밀번호 변경**으로 비밀번호를 바꿉니다.
   - Railway Variables에서 `ADMIN_PASSWORD`를 **삭제**합니다. 관리자는 계정이 하나도 없을 때만 만들어지므로 지워도 문제없습니다.
   - **선생님 관리**에서 선생님 계정을 추가합니다.

이후 GitHub의 해당 브랜치에 코드가 push되면 Railway가 자동으로 다시 배포하고, 데이터는 볼륨에 그대로 남습니다.
SQLite 파일을 쓰는 구조라 **Replicas(인스턴스 수)는 1로 유지**하세요.

#### 다른 클라우드를 쓸 경우
`Dockerfile`을 지원하는 서비스(Fly.io, Render 유료 플랜, 일반 VPS 등)면 같은 방식으로 운영할 수 있습니다. 조건은 세 가지입니다.
1. 영구 볼륨을 `/data`에 연결합니다.
2. HTTPS로 운영하면서 `TRUST_PROXY=1`, `COOKIE_SECURE=1`을 설정합니다.
3. 인스턴스는 1개만 실행합니다.

## 백업과 복구
- **백업**: 관리자 화면 **선생님 관리 → 백업 파일 다운로드** (`.db` 파일 1개).
- **복구**: 서버를 멈추고, 받아둔 파일을 `DB_PATH` 위치에 같은 이름으로 덮어쓴 뒤 다시 시작합니다.
- 백업 파일 안에는 학생 개인정보가 들어 있습니다. 보관 장소에 주의하세요.

## 관리자 비밀번호를 잊었을 때
서버 콘솔에서 아래 명령을 실행합니다. 계정이 이미 있으면 관리자 권한과 비밀번호가 재설정됩니다.
```bash
npm run admin -- create 이메일 이름 "새비밀번호"
npm run admin -- list      # 계정 목록 보기
```

## 개발
```bash
npm test     # API 자동 테스트 (임시 DB 사용)
```
- `server.js`: 웹 서버, 로그인/세션, 요청 처리
- `lib/store.js`: DB 스키마와 업무 규칙(저장·권한·충돌 검사·로그)
- `public/index.html`: 화면 (빌드 과정 없는 단일 파일)
- `scripts/`: 관리자 명령, 데모 데이터
- `Dockerfile`, `railway.json`: 클라우드 배포 설정 (`/healthz` 상태 확인)
