# REVERA Compass (데스크 공용 학생관리)

데스크 선생님들이 함께 쓰는 학생 관리 웹사이트입니다. 외부 서비스 없이 독립적으로 동작합니다.

- **서버**: Node.js (Express)
- **DB**: SQLite 파일 1개 (`data/revera.db`). 백업은 이 파일을 복사하면 됩니다.
- **로그인**: 자체 계정(이메일 + 비밀번호). 관리자가 선생님 계정을 만들어줍니다.

## 기능

### 사용자 역할

학생 지원대학의 대학은 **목록에서만 선택**합니다(목록에 없으면 관리자가 추가). **대학 → 전형**을 고르면 마감일이 자동으로 들어가고, 대학 정보에서 전형 마감일을 고치면 연결된 학생 마감일도 함께 바뀝니다(학생별 “직접 지정” 제외). 대학 목록 추가·삭제·이름 변경은 관리자만, 나머지 내용은 컨설턴트도 수정할 수 있습니다. 처음 실행 시 홍콩·싱가폴·캐나다·한국 14개 대학의 2027년 입학 초기 자료가 “확인 필요” 상태로 들어갑니다(`lib/university-seed.js`).

연간 계약의 종료 연월은 직접 입력할 수 있고, 비워 두면 시작 연월 기준으로 1학기 = 6개월, 1년 = 12개월로 계산합니다(갱신 알림에 사용).

공동 사용과 보안:
- **동시 수정 방지**: 다른 선생님이 먼저 저장한 항목을 덮어쓰려고 하면 저장이 거부되고 안내가 표시됩니다.
- **삭제는 모두 휴지통으로** 이동하며, 영구 삭제는 관리자가 휴지통에서만 할 수 있습니다.
- 열어둔 화면은 2분마다 자동으로 새로고침됩니다.
- 입력 창은 바깥을 눌러도 닫히지 않습니다(취소/Esc로 닫기, 입력 중이면 확인).
- 비밀번호는 scrypt 해시로 저장하고, 원문은 저장하지 않습니다. 로그인 5회 실패 시 15분 잠금.
- 비밀번호는 6자 이상. 첫 로그인 때 변경을 강제하지 않으며(각자 상단 “비밀번호 변경”), 비활성화·역할 변경 시 즉시 로그아웃됩니다.
- 업로드 파일: PDF·이미지·워드·엑셀·한글, 20MB 이하. `DB_PATH`와 같은 폴더의 `files/`에 저장됩니다(Railway에서는 볼륨 `/data/files`).
- 이전 버전 DB는 서버를 시작할 때 자동으로 새 구조로 업그레이드됩니다(기존 데이터 유지). 이전의 "선생님" 역할은 **컨설턴트**로 바뀝니다.

## 내 컴퓨터에서 실행해보기

[Node.js](https://nodejs.org) 20 이상(LTS 버전 권장)이 필요합니다.

```bash
cd student-manager
npm install
npm run demo                          # 샘플 데이터가 든 데모 DB 생성
DB_PATH=data/demo.db npm start        # http://localhost:3000
# 로그인(비밀번호 demo-pass-1): admin@demo.test 관리자 / staff@demo.test 관리팀 / kim@demo.test 컨설턴트
```

Windows PowerShell에서는 `$env:DB_PATH="data/demo.db"; npm start` 로 실행합니다.

## 실제 운영 시작

```bash
npm install
npm run admin -- create 원장님이메일@example.com 원장님이름 "처음비밀번호6자이상"
npm start
```
접속한 뒤 **계정 관리 → + 계정 추가**로 관리팀·컨설턴트 계정을 만들고, 임시 비밀번호를 각자에게 직접 전달합니다.

### 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 포트 |
| `DB_PATH` | `./data/revera.db` | DB 파일 위치. **클라우드에서는 반드시 영구 저장소(볼륨) 경로로 지정** |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | – | 계정이 하나도 없을 때 첫 실행에서 관리자를 자동 생성 (명령어를 쓸 수 없는 클라우드용) |

## 어디에 띄울까 (배포 방법)

### A. 학원 PC에 설치 (내부망 전용)
- 항상 켜두는 PC 한 대에 위 “실제 운영 시작” 순서대로 설치합니다.
- 같은 와이파이/네트워크에 있는 선생님은 `http://그PC의IP:3000`으로 접속합니다. PC의 IP는 Windows에서 `ipconfig`로 확인합니다.
- 비용이 들지 않고 데이터가 학원 밖으로 나가지 않습니다.
- 대신 **학원 밖에서는 접속할 수 없습니다.** 이 PC를 인터넷에 직접 열어두는 것(포트포워딩)은 권장하지 않습니다. HTTPS가 없어서 비밀번호가 암호화되지 않은 채로 전송됩니다.
- PC가 고장나면 데이터도 잃을 수 있으니 **백업 다운로드를 정기적으로** 해두세요.

### B. 클라우드 — Railway (권장, 어디서나 접속)

> 아래 버튼 이름과 메뉴 위치는 2026년 10월 기준이며, Railway 화면이 바뀌면 다를 수 있습니다.
> 요금(공식 문서 기준): Hobby 플랜 **월 $5**이고, 그 $5가 사용량 크레딧으로 포함됩니다. 볼륨은 서비스당 기본 **5GB**입니다.
> 이 사이트 규모면 $5 안에서 해결될 것으로 예상하지만 실측한 값은 아닙니다. 첫 달에 **Usage** 화면에서 실제 사용량을 확인하세요.

1. **가입**: https://railway.com 에서 GitHub 계정으로 가입하고 **Hobby 플랜**을 결제합니다.
   무료(Free/Trial) 플랜은 볼륨이 0.5GB이고 사용량 제한이 있어서 운영용으로는 권장하지 않습니다.
2. **프로젝트 생성**: **New Project → Deploy from GitHub repo**에서 `revera-assessment` 저장소를 고릅니다.
   GitHub 권한을 묻는 창이 뜨면 이 저장소에 대한 접근을 허용합니다.
3. **서비스 설정** (생성된 서비스 클릭 → **Settings**)
   - **Source → Root Directory**: `/student-manager`
   - **Source → Branch**: 사이트 코드가 있는 브랜치를 고릅니다(main에 합친 뒤라면 `main`).
   - **Config-as-code → Railway Config File**: `/student-manager/railway.json`
     설정 파일은 Root Directory를 따라가지 않아서 전체 경로로 적어야 합니다. 이 칸을 비워둬도 Dockerfile을 자동으로 찾아 배포하고, 상태 확인(health check)만 빠집니다.
4. **볼륨 추가 (가장 중요)**: 프로젝트 화면에서 서비스를 우클릭하거나 **+ Create → Volume**을 눌러 볼륨을 만들고, 이 서비스에 연결합니다.
   - **Mount path**: `/data`
   - 이 단계를 빼먹으면 재배포할 때마다 **모든 데이터가 사라집니다.**
5. **환경변수** (서비스 → **Variables**)

   | 이름 | 값 |
   |---|---|
   | `ADMIN_EMAIL` | 원장님 이메일 |
   | `ADMIN_NAME` | 원장님 이름 |
   | `ADMIN_PASSWORD` | 처음 비밀번호(6자 이상) |
   | `TRUST_PROXY` | `1` |
   | `COOKIE_SECURE` | `1` |

   `PORT`는 Railway가 자동으로 넣어주니 직접 넣지 않습니다.
6. **주소 만들기**: **Settings → Networking → Generate Domain**을 누르면 `https://xxxx.up.railway.app` 주소가 생깁니다. 이 주소가 사이트입니다.
   학원 도메인(예: `students.revera.co.kr`)을 쓰려면 같은 화면의 **Custom Domain**에 입력하고, 안내에 나오는 DNS 레코드를 도메인 업체 설정에 추가합니다.
7. **배포 확인**: **Deployments** 탭에서 배포가 *Success*가 되면, 위 주소로 접속해 `ADMIN_EMAIL` / `ADMIN_PASSWORD`로 로그인합니다.
8. **마무리 보안 조치**
   - 로그인한 뒤 바로 **비밀번호 변경**으로 비밀번호를 바꿉니다.
   - Railway Variables에서 `ADMIN_PASSWORD`를 **삭제**합니다. 관리자는 계정이 하나도 없을 때만 만들어지므로 지워도 문제없습니다.
   - **계정 관리**에서 관리팀·컨설턴트 계정을 추가합니다.

이후 GitHub의 해당 브랜치에 코드가 push되면 Railway가 자동으로 다시 배포하고, 데이터는 볼륨에 그대로 남습니다.
SQLite 파일을 쓰는 구조라 **Replicas(인스턴스 수)는 1로 유지**하세요.

#### 다른 클라우드를 쓸 경우
`Dockerfile`을 지원하는 서비스(Fly.io, Render 유료 플랜, 일반 VPS 등)면 같은 방식으로 운영할 수 있습니다. 조건은 세 가지입니다.
1. 영구 볼륨을 `/data`에 연결합니다.
2. HTTPS로 운영하면서 `TRUST_PROXY=1`, `COOKIE_SECURE=1`을 설정합니다.
3. 인스턴스는 1개만 실행합니다.

## 자동 백업(구글 드라이브)·이메일 알림
관리자 메뉴 **관리 › 백업·알림**에서 설정합니다. 원장님 구글 계정에 **Google Apps Script 웹 앱**(`scripts/google-apps-script.gs`)을 한 번 설치하면, Compass 서버가 그 웹 앱을 통해
- 매일 정해진 시각(중국 시간)에 백업 ZIP을 내 드라이브의 **“Compass 백업”** 폴더에 저장하고(최근 30개 유지),
- 매일 아침 선생님마다 **“오늘 챙길 일”** 메일(내 팔로업: 기한 지남·3일 이내 / 담당 학생 지원 마감: 7일 이내)을 보냅니다. 보낼 내용이 없는 선생님은 건너뜁니다.

설치 순서는 설정 화면의 “처음 연결하는 방법”에 있습니다(코드 복사 → script.google.com 새 프로젝트에 붙여넣기 → 웹 앱으로 배포(실행: 나, 액세스: 모든 사용자) → 웹 앱 URL을 설정에 저장 → 연결 확인).
- 웹 앱은 Compass가 만든 **비밀 키**가 맞을 때만 동작합니다. 비밀 키를 새로 만들면 코드를 다시 붙여넣고 새로 배포해야 합니다.
- 메일은 그 구글 계정 이름으로 발송되며, 구글 계정의 하루 발송 한도가 적용됩니다.
- 선생님별 알림 끄기: 계정 관리 › 수정 › “이메일 알림”.
- 백업 실패 시 10분마다 다시 시도하고, 결과는 설정 화면의 “마지막 백업/알림”에 표시됩니다.

## 백업과 복구
- **백업**: 관리자 화면 **계정 관리 → 백업 파일(ZIP) 다운로드**. ZIP 안에 `compass.db`(학생·기록·계약·입금·변경 기록), `files/`(업로드한 파일 전체), `파일목록.csv`(저장 이름 ↔ 학생·원래 파일 이름), `복구방법.txt`가 들어 있습니다.
- **복구**: 서버를 멈추고 `compass.db`를 `DB_PATH` 위치에 같은 이름으로 덮어쓴 뒤, `files/` 안의 파일을 `DB_PATH`와 같은 폴더의 `files/`에 넣고 다시 시작합니다.
- 사이트 계정 비밀번호는 “계정” 탭에 그대로 보입니다(복사 버튼). DB에도 암호화 없이 저장됩니다.
- 백업 파일 안에는 학생 개인정보·계약 금액·**사이트 계정 비밀번호**가 들어 있습니다. 보관 장소에 주의하세요.

## 기존 데이터 가져오기
파일에 `"mode": "append"`가 있으면 이미 있는 학생에게 기록(미팅 등)만 덧붙이고, 같은 원본 링크·날짜·시간의 기록은 다시 가져와도 중복되지 않습니다. 가져온 미팅·상담기록은 “확인 필요”로 표시됩니다. 덧붙이기 모드에서는 기존 학생의 **비어 있는 칸만** 채우고(`appendMemo`는 메모 끝에 한 번만 이어 붙임), 계정은 `university` 이름으로 대학 목록에 연결되며, 계정(사이트+아이디)·학력(학교+시작일)도 중복 없이 들어갑니다. 새로 쓰인 학교·커리큘럼은 목록에 자동 추가됩니다.

**계정 관리 → 기존 데이터 가져오기**에서 `compass-import-v1` 형식의 JSON 파일을 선택하면 학생과 계약·지원대학·성적·서류·링크·상담기록·팔로업·전공 후보·학력·수강 과목·사이트 계정을 한 번에 등록합니다. 같은 이름의 학생이 이미 있으면 그 학생은 건너뜁니다. 파일에 문제가 있으면 아무것도 등록되지 않습니다(전체 취소).

